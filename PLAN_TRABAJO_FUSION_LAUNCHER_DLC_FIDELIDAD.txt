1. DIAGNÓSTICO Y ANÁLISIS DE LA SITUACIÓN ACTUAL
================================================================================
Actualmente el ecosistema cuenta con:
1. Panda Launcher (WPF / .NET 8, versión 2.4.16):
   - Gestiona inyecciones de Steam, parches LUA de OpenSteamTool y tickets.
   - Tiene el botón "🚀 Activar" que inyecta el juego al cliente de Steam.
   - Si el juego es Denuvo (detectado por DenuvoGamesHelper), abre WhatsApp para
     pedir token manual.
2. PandaStore Activador (Python / PyWebView / PyInstaller):
   - Herramienta especializada en dos pasos:
     * Paso 1: Generar reporte de Steam ingresando el Steam AppID.
     * Paso 2: Canjear el código de activación de 6 caracteres.
   - Problema actual: El cliente debe descargar 2 programas por separado y escribir
     manualmente el AppID en el activador, generando dudas, soporte y errores tipográficos.
3. Pedidos y Claves (Web):
   - En MisPedidos.js y Cyber Vault, los pedidos que tienen un campo `licenseKey`
     pueden ser visualizados por el usuario aunque su estado sea "pendiente" o "rechazado".
   - Riesgo: Si un usuario envía un pedido por transferencia y adjunta un comprobante
     falso o inexistente, podría tener acceso inmediato a la key de Steam antes de
     que el administrador verifique el dinero en la cuenta bancaria.

2. MÓDULO 1: FUSIÓN DE PANDA LAUNCHER 2.4.16 Y PANDASTORE ACTIVADOR
================================================================================
2.1. Reestructuración de Botones en la Tarjeta de Juego (MainWindow.xaml)
--------------------------------------------------------------------------------
Actualmente, cada juego en el catálogo del Launcher muestra:
- Botón 1: "🚀 Activar" (que inyecta tickets y agrega el juego a Steam).
- Botón 2: "🛠️ Fix" (descarga e instala el fix de traducción/crack/online).
- Botón 3: "🎮 Jugar" (lanza el juego vía Steam o ejecutable).

NUEVA ESTRUCTURA DE BOTONES:
- Botón Principal A: "📥 Agregar a la biblioteca"
  * Reemplaza el texto del botón actual "🚀 Activar".
  * Función: Inyecta el manifiesto/tickets a Steam y deja el juego listo para descargar.
  * Se aplica a todos los juegos que el cliente tenga autorizados.
- Botón Principal B: "🔑 Activar" (Estilo llamativo VIP Dorado / Púrpura Neón)
  * Visible ÚNICAMENTE en juegos que requieran activación VIP:
    ~80 juegos con Denuvo (Black Myth Wukong, Persona 3 Reload, etc.),
    7 juegos de Ubisoft (Assassin's Creed Shadows, Far Cry 6, Avatar, Star Wars Outlaws, etc.),
    7 juegos de EA Games (FC 25, NFS Unbound, Madden, etc.).
  * Al hacer clic: Ejecuta el flujo del Activador PandaStore con el AppID precargado.

2.2. Flujo del Nuevo Botón "Activar" para Juegos VIP
--------------------------------------------------------------------------------
Al presionar "🔑 Activar" en un juego VIP:
1. El Launcher comprueba si el juego está en la lista de títulos VIP/Denuvo.
2. Extrae el AppID exacto del juego (ej: 2358720 para Wukong, 1081 para AC Shadows).
3. Lanza el Activador integrado de PandaStore pasando el AppID por parámetro
   (ej: `PandaStoreActivator.exe --appid 2358720 --autofill`).
4. El cliente ve abrirse la ventana del Activador PandaStore de inmediato,
   con el Paso 1 ("Generar Reporte de Steam") ya completado con el AppID ingresado,
   e incluso con el botón de "Iniciar Reporte" listo para ejecutar en 1 clic.
5. El cliente obtiene su reporte y en el Paso 2 ingresa el código otorgado
   en la web o por el administrador para jugar al instante.

2.3. Bridge Launcher -> Activador (Precarga del AppID)
--------------------------------------------------------------------------------
Mecanismo de comunicación entre C# (.NET 8) y el Activador (PyWebView / Python):
- Opción 1 (Parámetro CLI):
  `Process.Start("PandaStoreActivator.exe", $"--appid {juego.AppId}");`
  En `tokeer_drm.py`: Se lee `sys.argv`, se detecta `--appid <valor>` y se envía
  a JavaScript mediante `WINDOW.evaluate_js($"window.__setAppId('{appId}')")`.
- Opción 2 (Archivo Bridge Temporal en %LOCALAPPDATA%/PandaStore/launch_bridge.json):
  Contiene `{ "appId": "2358720", "gameName": "Black Myth: Wukong", "timestamp": ... }`.
  Al iniciar, el Activador lee este archivo si existe y precarga la interfaz.
- En la interfaz web del Activador (`index.html`):
  El campo `#validatorAppId` se rellena automáticamente y se resalta visualmente
  en color verde esmeralda: "AppID detectado automáticamente desde Panda Launcher".

2.4. Unificación de Instalación y Empaquetado
--------------------------------------------------------------------------------
Para que el cliente descargue UN SOLO archivo y no dos cosas separadas:
- El instalador oficial `PandaStoreSetup.iss` (Inno Setup) incluirá:
  * `PandaStoreLauncher.exe` (Launcher C#)
  * `PandaStoreActivator.exe` (Activador de tokens Denuvo / Ubisoft / EA)
  * Todas las librerías necesarias (dwmapi.dll, xinput1_4.dll, etc.)
- Al instalar el Launcher, el Activador queda ubicado en la misma carpeta o subdirectorio `tools/`.
- En caso de que el cliente ejecute el Launcher sin el activador presente (por ejemplo versión portable),
  el Launcher tendrá una función de descarga silenciosa automática del activador desde el CDN oficial
  de PandaStore (Firebase Storage / Gofile CDN).

3. MÓDULO 2: GESTIÓN DE JUEGOS BASE Y DLCs INTELIGENTES
================================================================================
3.1. Arquitectura de Licencias en Base de Datos (Firestore: /licenses/{key})
--------------------------------------------------------------------------------
Cada clave `PANDA-XXXX-YYYY` cuenta con:
- `allowed_games`: Array de AppIDs o nombres de juegos base autorizados (ej: ["1091500"]).
  Si tiene ["*"], tiene acceso a todo el catálogo.
- `allowed_dlcs`: Array de AppIDs específicos de DLCs que el cliente ha adquirido
  (ej: ["2138330", "1826070"]).

3.2. Activación Granular en el Launcher
--------------------------------------------------------------------------------
1. Compra de SOLO Juego Base:
   - En el panel de administrador, al aprobar el pedido, se genera o asocia la clave
     con `allowed_games: [AppIdBase]` y `allowed_dlcs: []` (vacío).
   - En el Launcher, al presionar "Agregar a la biblioteca", `SteamManager.ActivarJuegoAsync`
     inyecta únicamente el juego base y NO habilita los DLCs en el archivo `.lua` / manifiesto.
2. Compra de Juego Base + DLCs:
   - La clave se crea con `allowed_games: [AppIdBase]` y `allowed_dlcs: [Dlc1, Dlc2, ...]`.
   - El Launcher inyecta tanto el juego base como los DLCs autorizados.
3. Compra de DLCs a posteriori (1 semana o 1 mes después):
   - El cliente ya tiene el juego base en su biblioteca.
   - El cliente compra los DLCs en la web o por WhatsApp.
   - El admin agrega los AppIDs de los DLCs al array `allowed_dlcs` de la misma licencia.
   - En el Launcher, el cliente vuelve a presionar "Agregar a la biblioteca" o "Actualizar DLCs",
     y el Launcher inyecta los nuevos DLCs de forma transparente sin tener que reinstalar el juego base.

3.3. Interfaz del Launcher: Showcase de DLCs Disponibles
--------------------------------------------------------------------------------
En la tarjeta de cada juego que tenga DLCs asociados en el catálogo (`ryuu_catalog`):
- Si el usuario NO tiene todos los DLCs adquiridos:
  * Se muestra un botón sutil o expandible: `🎁 DLCs Disponibles (X nuevos)`.
  * Al desplegarlo, aparece una lista elegante estilo Dark Glassmorphism con:
    - Portada / Banner pequeño del DLC.
    - Nombre del DLC y AppID.
    - Precio unitario ($1.000 CLP) y ofertas por pack.
    - Checkbox para marcar los DLCs que desea comprar.
    - Si un DLC ya está adquirido, se muestra con una insignia verde: "✔ En tu biblioteca".

5. MÓDULO 4: BLINDAJE DE SEGURIDAD EN PEDIDOS Y ENTREGA DE KEYS
================================================================================
5.1. Diagnóstico del Bug de Pedidos Pendientes
--------------------------------------------------------------------------------
Causa raíz identificada:
- En `MisPedidos.js`:
  1. La tarjeta `PedidoCard` renderizaba `{pedido.licenseKey ? <div className="vault-key-code">...</div> : null}`
     sin condicionar a `estado === "exitoso"`.
  2. En el Tab "Cyber Vault" (Licencias), `allKeys` filtraba `allUserPedidos.filter(p => Boolean(p.licenseKey))`
     sin validar si el pedido de origen fue pagado y aprobado.
  3. En ciertos flujos manuales de prueba o fallback, se llamaba a `generarKeyDirectaFallback`
     sin exigir validación estricta de aprobación bancaria.

5.2. Regla Inquebrantable de Despacho (Zero-Trust)
--------------------------------------------------------------------------------
Una clave de Steam / Launcher o acceso a juegos NUNCA debe mostrarse al cliente
a menos que se cumplan las siguientes condiciones estrictas:
`esAprobado = (pedido.transferenciaEstado === "exitoso") || (pedido.estado === "exitoso") || (!esManual && pedido.status === "approved");`

Comportamiento por Estado:
- ESTADO PENDIENTE:
  * La tarjeta muestra el badge amarillo "Pendiente de verificación".
  * La sección de clave NO muestra ningún código. En su lugar muestra:
    "⏳ Tu clave se liberará automáticamente una vez que el administrador verifique tu comprobante bancario."
  * El Tab de Licencias ("Cyber Vault") NO lista claves de pedidos pendientes ni rechazados.
- ESTADO RECHAZADO:
  * Badge rojo "Rechazado".
  * Clave completamente bloqueada / eliminada de la vista. Mensaje: "Pago rechazado o comprobante no válido."
- ESTADO EXITOSO:
  * Badge verde "Exitoso".
  * Se genera y muestra la clave `PANDA-XXXX-YYYY` con botón de copia y acceso al Launcher.

5.3. Medidas en Cloud Functions y Base de Datos
--------------------------------------------------------------------------------
- En `functions/index.js`, asegurar que `generatePandaLicenseAndSendEmail` solo se ejecute
  cuando `esConfirmado === true` (`estadoActual === "exitoso"`).
- Si el administrador rechaza un pedido que por error previo tenía una clave asignada,
  el sistema suspende o elimina la clave en la colección `/licenses` (`status: "suspended"` o `"revoked"`).

6. OPINIONES TÉCNICAS, MEJORAS Y RECOMENDACIONES ESTRATÉGICAS
================================================================================
Propuestas de valor añadido para enriquecer el proyecto:

1. Detección Inteligente en el Launcher de Juegos Instalados vs No Instalados:
   - Si el juego está en la biblioteca pero no instalado, el botón "Agregar a la biblioteca"
     debe indicar "✔ Ya en biblioteca - Instalar desde Steam" para no confundir al usuario.
2. Alerta de Exclusiones de Antivirus / Windows Defender Automatizada:
   - Los activadores de Denuvo/OST suelen generar falsos positivos con Windows Defender.
   - Incluir en el Launcher un botón de 1-clic: "🛡️ Agregar exclusión a Windows Defender"
     que ejecute el comando PowerShell oficial de exclusión de la carpeta de Steam y Panda Launcher.
3. Notificación Push o Correo cuando el Admin Aprueba el Pedido:
   - Cuando el admin cambia el estado de "Pendiente" a "Exitoso" en el panel, el cliente
     recibe un correo instantáneo con su clave, y si tiene la web abierta, la página se actualiza
     en tiempo real (Firestore onSnapshot) mostrando la clave al segundo.
4. Historial de Recompensas de Fidelidad en Perfil:
   - Que el usuario pueda ver cuántos regalos ha desbloqueado a lo largo del tiempo,
     fomentando el sentido de pertenencia y compra continua.
